## 方法

实际使用 Claude Code 2.1.294，模型 `anthropic/claude-opus-5-5`。每次启动新会话，只提供下表中的一句任务。没有追加格式提示、纠正消息或额外系统提示；使用 Claude Code 自身的全局文件加载机制。

两个合成项目用于严格核对文件、类名、同名符号和跨项目归属；另一个 Case 使用私有 Java 发货项目源码。仅允许 Read、Glob、Grep。CLI 继承的旧代理造成最初 405，仅对测试子进程复用已有本机网关路由并排除 loopback 代理，没有修改持久模型、代理配置。

通过临时本机转发器检查实际模型请求是否含已安装规则正文，记录布尔值和 SHA-256，不记录请求体或凭据。Claude 加载器会去掉 HTML 管理注释，因此最终核验正文而非整个带注释文件；最终批次 16/16 请求均包含完整正文和全局文件来源。

## 发现与调整

原 49 行规则生成了 61 个有效文件链接，但其中 3 个标签用了“第 N 行 / call site”；跨项目目标相对于共同工作区而不是所属项目根。第一轮短版修正了跨项目路径，但偶尔仍输出位置标签。

最终只加强一条：字段、调用点和重复位置也使用所属类或所属方法作标签，输出前核对所有标签。没有给单次任务增加提示词，也没有不断添加示例。最终批次结果：

- 65/65 链接标签是真实完整符号，文件存在、行号有效，正文无本机绝对路径。
- 40/40 方法链接的行号位于对应方法范围。
- 跨项目 10/10 链接目标相对所属项目根，项目标签正确；同项目不额外添加项目名。
- 严格类体检查有一条例外：类级链接指向其所属文件的 import 行，用于解释依赖；已单独记录，并非指向错误文件或方法。

## CodeJump 实际解析

将每个原始 Markdown 链接独立传入 release CLI 的 parser/resolver，并使用各用例对应的项目索引。65/65 均识别并找到正确项目、文件和原始行号候选。私有项目中的两个重载引用保留选择确认，其他重载候选不会自动打开。

同时修正了程序侧的跨项目标签处理：Markdown 和 AX 链接都保留标签项目名；标签与目标冲突时保留目标依据并要求确认。
